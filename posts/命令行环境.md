首先第一个问题在于，什么是命令行环境？

命令行环境：即cli程序所遵循的约定、生态。主要包含：命令行界面（cli）、远程机器、终端复用器、定制shell、shell中的AI、终端模拟器。

其次，什么是命令行工具？

命令行工具就是 `ls`、`grep` 这些程序,分 GNU 版（LInux）和 BSD 版（macOS），`ls --all` 的差异就源于命令行工具的不同。

## 命令行界面

#### 参数

参数即— cli程序在执行时接收的字符串。对于大多数程序，参数通常由**选项（flags）**和普通字符串组成，选项通常是可选的，用来修改程序的行为。

选项分为长名称的双横线选项（如·`--all`），以及单字母的单横线选项（如 `-a`），很多情况下两种格式等价。单横线选项通常可以合并，顺序也无所谓。

在 Shell 脚本内部，可以通过特殊语法访问这些参数。 `$1` 访问第一个参数，`$2` 到 `$9` 以此类推。`$@` 以列表形式访问所有参数，`$#` 获取参数个数，`$0` 则是程序本身的名称。且支持传入不定数量的同类型参数，配合通配符扩展可实现批量操作。

#### 流

使用管道运算符 `|` 时，Shell 操作的就是从前一个程序流向后一个程序的数据流。且Shell 会先创建所有进程并连接好它们的流，而不是等一个结束再启动下一个：

```bash
ubuntu@linux:~/missing-semester/demo$ (sleep 15 && cat numbers.txt) | grep -P '^\d$' | sort | uniq  &
[2] 4879
ubuntu@linux:~/missing-semester/demo$ ps | grep -P '(sleep|cat|grep|sort|uniq)'
   4877 pts/0    00:00:00 grep
   4878 pts/0    00:00:00 sort
   4879 pts/0    00:00:00 uniq
   4881 pts/0    00:00:00 sleep
   4892 pts/0    00:00:00 grep
```

每个程序都有一个输入流，叫 stdin（standard input，标准输入），使用管道时，stdin 会自动连接。有两个输出流：stdout 和 stderr。 stdout 是最常见的输出，也是默认会通过管道传给下一个命令的。 stderr 是另一条流，程序用它输出警告和其他问题信息，这样这些内容就不会被管道中的下一个命令当成正常数据处理。

#### 变量

在 bash 里，给变量赋值写成 `foo=bar`，读取变量值用 `$foo`。注意 `foo = bar` 是非法语法，因为 Shell 会把它解析成调用程序 `foo`，并传入参数 `['=', 'bar']`。 在 Shell 中，空格的作用就是分隔参数。

```bash
ubuntu@linux:~/missing-semester/demo$ foo = bar
Command 'foo' not found, did you mean:
  command 'fox' from deb objcryst-fox (2022.1-2build1)
  command 'foot' from deb foot (1.25.0-1)
  command 'fop' from deb fop (1:2.10+dfsg-2)
  command 'goo' from deb goo (0.155+ds-6build1)
  command 'fio' from deb fio (3.41-2)
Try: sudo apt install <deb name>
ubuntu@linux:~/missing-semester/demo$ foo=bar
ubuntu@linux:~/missing-semester/demo$ 
```

Shell 变量没有类型，本质上全都是字符串。 还要注意，单引号和双引号在 Shell 中并不能互换。 `'` 包起来的是字面量字符串，不展开变量、不做命令替换、也不处理转义序列；`"` 包起来的则会。

```bash
ubuntu@linux:~/missing-semester/demo$ echo $foo
bar
ubuntu@linux:~/missing-semester/demo$ echo '$foo'
$foo
ubuntu@linux:~/missing-semester/demo$ echo "$foo"
bar
```

简单来说就是：单引号 `' '` 会禁止变量展开，里面所有字符都当普通文本，不进行任何解释。双引号 `" "` 允许变量展开；不加引号也允许展开。

命令替换： `$(命令)` 或反引号 ``命令``，把命令的标准输出当作字符串嵌入到当前命令行里。。

```bash
files=$(ls)
echo "$files" | grep README
echo "$files" | grep ".py"
```

**进程替换：**`<(命令)` 输入型，`>(命令)` 输出型，把命令的输入/输出伪装成一个文件路径，供那些"只认文件参数"的程序使用。

如：`<( CMD )` 会执行 `CMD`，把输出存入临时文件，再用临时文件名替换掉 `<()`。`<( CMD )` 会执行 `CMD`，把输出存入临时文件，再用临时文件名替换掉 `<()`。

每当 Shell 程序调用另一个程序时，它会顺带传过去一组变量，这些就是*环境变量（environment variables）*。	

怎么查看环境变量？

```bash
printenv
```

怎么给某个命令传环境变量？想显式给某个命令传环境变量，可以在命令前面直接加赋值：

```shell
ubuntu@linux:~/missing-semester/demo$ TZ=Asia/Tokyo date
Sun Jul 19 02:34:53 JST 2026
ubuntu@linux:~/missing-semester/demo$ date
Sun Jul 19 01:34:59 CST 2026
```

另一种方式是用内建命令 `export`，它会修改当前 Shell 的环境，之后启动的所有子进程都会继承这个变量：

```shell
ubuntu@linux:~/missing-semester/demo$ export DEBUG=1
ubuntu@linux:~/missing-semester/demo$ echo $DEBUG
1
```

怎么删除一个变量？要删除一个变量，可以使用内建命令 `unset`，例如 `unset DEBUG`。

#### 返回码

默认情况下，Shell 脚本返回退出码 0，0 表示一切正常，非 0 表示执行中遇到了问题。 要主动返回非零退出码，使用内建命令 `exit NUM`，该返回码可以通过 `$?` 获取。

Shell 里有布尔运算符 `&&` 和 `||`，分别表示 AND 和 OR。 但与普通编程语言不同，Shell 中这两个运算符基于程序的返回码来工作。 它们也都是[短路](https://en.wikipedia.org/wiki/Short-circuit_evaluation)运算符。 也就是说，你可以根据前一个命令是否成功来条件性地执行后续命令，「成功」的判断标准就是返回码是否为 0。

同样的原则也适用于 `if` 和 `while` 语句，它们也是根据返回码来做判断的。

#### 信号

信号是内核提供的一种进程间异步通知机制。 当进程收到信号时，它会暂停当前执行来处理信号，并根据信号携带的信息决定是否改变后续执行流程。所以信号本质上是一种*软件中断（software interrupt）*。

信号可以杀进程、暂停进程。可以使用内建命令 `trap`，让脚本在收到信号时执行指定命令。

## 基于SSH连接远程机器

```shell
ssh alice@server.mit.edu
```

非交互式执行：**SSH 是流透明的**，stdin/stdout/stderr 都能正常穿过网络，所以远程命令可以像本地命令一样接进管道。
